# 바이브 팀 OS *(테스트품)*

**Git을 몰라도 여러 명이 AI로 함께 만들 수 있게 하고, 그 과정에서 "왜 그렇게 정했는지"가 자동으로 남는 Claude Code 스킬.**

> 아직 만드는 중입니다. 아래 「지금 되는 것 / 안 되는 것」을 먼저 읽어주세요.

---

## 무엇을 하나

```
세팅 → 기획(의도 자동 기록) → PRD 병합(기여자 추적) → 발표물
```

- **커밋 이전의 실시간 가시성** — GitHub은 커밋된 것만 보여줍니다
- **자동으로 남는 "의도"** — 대화 덤프가 아니라 정제된 결정만 남습니다
- **아이디어 단위 기여 귀속** — 코드에는 `git blame`이 있는데 아이디어에는 없습니다

## 설치

`vibe-team-os` 폴더를 스킬 폴더에 연결하면 플러그인으로 잡힙니다.

**Windows**

```bash
cmd /c mklink /J "%USERPROFILE%\.claude\skills\vibe-team-os" "<받은경로>\vibe-team-os"
```

**macOS · Linux**

```bash
ln -s "<받은경로>/vibe-team-os" ~/.claude/skills/vibe-team-os
```

**설치 후 Claude Code를 다시 시작해야 합니다.** 자동 기록은 세션이 시작될 때 붙습니다. 재시작하지 않으면 아무 오류 없이 기록만 안 남습니다.

확인:

```bash
bash vibe-team-os/scripts/verify_hooks.sh
```

세팅 직후에는 "자동 기록이 꺼져 있습니다"가 정상입니다. 아직 대화가 한 번도 안 오갔기 때문입니다. 한 턴 지난 뒤 다시 돌려서 **"자동 기록 정상"** 이 나오면 붙은 것입니다.

## 써보기

새 폴더에서 Claude Code를 열고 이렇게 말하면 됩니다.

```
팀 프로젝트 시작하자
```

혼자 쓰실 거면 팀원을 1명으로 두면 됩니다. `mode: solo` 로 잡히고 병합과 기여 귀속만 꺼집니다. GitHub을 안 쓰실 거면 설정에 `"remote": "none"` 을 넣으면 원격 없이도 세팅이 완료됩니다.

## 화면 미리보기

`demo/` 는 **가짜 데이터로 화면 8종을 보는 곳**입니다. 사람 이름·기록·PRD 항목 전부 만들어낸 것입니다.

```bash
python -m http.server 8766 --directory demo
```

혼자서 하루 만에 쌓은 기록으로는 볼 수 없는 상태들이 들어 있습니다 — 22일 방치된 질문, 판단 변경, 초대 수락 대기, 추적 못 한 PRD 항목.

날짜를 다시 맞추려면:

```bash
python tools/make_demo.py
```

## 지금 되는 것 / 안 되는 것

| | |
|---|---|
| 세팅 (검사 20항목) | ✅ 실물 확인 |
| 자동 기록 (hook 5종) | ✅ 실물 확인 |
| 의도 로그 · 형식 검사 | ✅ 실물 확인 |
| 대시보드 화면 8종 | 🔶 6종은 실물, **PRD·기여도는 더미로만** |
| PRD 병합 | ⬜ 안 해봤습니다 |
| 발표물 생성 | ⬜ 안 해봤습니다 |
| 실시간 공유 (DB) | ⬜ 권한 설정은 검증했으나 연결은 안 해봤습니다 |

**의도 정확도는 아직 측정 전입니다.** 이 도구의 핵심은 "AI가 뽑은 의도가 맞느냐"인데, 그 수치가 없습니다. 쓰시면서 로그의 「실제 목적」이 실제와 맞는지 봐주시면 그게 제일 필요한 피드백입니다.

## 알려진 한계

- **참조 문서 4종이 비어 있습니다** — `merge` · `report` · `policies` · `troubleshooting`. 해당 단계에 가면 스킬이 대신 읽을 설계 문서를 알려줍니다
- **공유 전 검사가 「세션을 연 폴더」를 봅니다.** `git push` 때만 도는 것은 맞는데, 명령이 다른 폴더로 이동해 push 하면 엉뚱한 저장소를 검사하고 통과시킵니다. 한 폴더에서 그 폴더를 push 하는 보통의 경우에는 문제없습니다
- **Windows PowerShell에는 `bash`가 없습니다.** Git에 딸려 있지만 경로에 안 잡힙니다. `& "C:\Program Files\Git\bin\bash.exe" ...` 로 부르거나, 그냥 Claude에게 확인해 달라고 하시면 됩니다
- 대시보드는 정적 파일이라 화면에서 내용을 고칠 수 없습니다. 고치는 것은 Claude가 합니다 — 화면에 `LOG-0003 고쳐줘` 같은 문장이 적혀 있습니다

```
demo/                            가짜 데이터로 보는 화면

```

## 원칙

**DB는 캐시, Git이 진실** — 실시간 상태는 빠르게 주고받되 결정은 반드시 파일로 굳힙니다.

**AI는 절충안을 만들지 않습니다** — 의견이 갈리면 두 안을 그대로 보여주고 사람이 고릅니다.

**근거가 없으면 빈칸으로 둡니다** — 말하지 않은 이유를 추측해 적으면 그 추측이 영구 기록이 되고 발표 자료까지 갑니다.

**조용한 실패를 만들지 않습니다** — 기록이 안 남고 있으면 화면 맨 위에 뜹니다.
