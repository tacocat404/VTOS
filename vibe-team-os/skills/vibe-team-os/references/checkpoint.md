## 왜 세션이 아니라 체크포인트인가

처음에는 "세션이 끝날 때 기록한다"로 잡았다. 그런데 GUI 로 하루 종일 한 세션을 열어두면 **끝이 오지 않는다.**

```
세션 끝에 기록  →  하루 종일 열어두면 아무것도 안 남는다
                →  남아도 한 장에 8시간이 뭉쳐 쓸모가 없다
```

> **세션 경계는 도구의 사정이고, 작업 경계는 사람의 사정이다.**
> 기록은 사람 쪽을 따라간다.

그래서 세션이 아니라 **작업 한 덩어리**를 기준으로 찍는다. 이러면 CLI 든 GUI 든, 노트북을 덮든 강제 종료되든 마지막 체크포인트까지는 남는다.

---

## 언제 찍는가 — 3중 트리거

### 0순위 · 대화가 압축되기 직전

대화가 길어지면 Claude Code 가 앞부분을 압축한다. **그 순간 원본 맥락이 사라진다.** 압축 후에 쓰려고 하면 이미 늦다.

`PreCompact` hook 이 `--force` 로 부른다. 여기서는 **무조건 찍는다.**

### 1순위 · 작업 한 덩어리가 끝났을 때

이건 사람이 판단한다. 아래 신호가 보이면 찍는다.

| 신호 | 예시 |
|---|---|
| 주제 전환 | "이제 온보딩 화면 보자" |
| 결정 도출 | 의도 로그를 만드는 순간 |
| 산출물 완성 | 기획서 한 섹션 끝, 문서 저장 |
| 사용자가 명시 | "이거 끝", "여기까지" |
| 긴 공백 후 재개 | 2시간 만에 돌아옴 |

### 2순위 · 10턴 안전망

1순위를 놓칠 수 있으니 그물을 하나 더 친다.

```
10턴 동안 한 번도 안 찍혔다  →  무조건 찍는다
```

**이게 없으면 조용히 아무것도 안 남는 사고가 난다.** "아직 덩어리가 안 끝났는데" 하며 40턴을 지나갈 수 있다.

## 무엇을 하는가 — 세 가지를 한꺼번에

```
체크포인트
   ├─ ① 정리   작업 노트에 지금까지 한 일을 추가
   ├─ ② 기록   결정이 있었으면 의도 로그 생성
   └─ ③ 공유   상태 갱신 → 대시보드 반영
```

③을 여기에 둔 이유가 있다. 턴마다 공유하면 커밋이 하루 수백 개로 폭증해서 사람이 읽을 히스토리가 묻힌다. **작업 덩어리 단위로 묶으면 그 문제가 같이 해결된다.**

②는 결정이 있을 때만이다. 조사만 한 구간이면 만들지 않는다.

---

## 작업 노트 쓰는 법

`members/<이름>/notes/2026-09-03.md` — **하루 한 파일에 누적한다.**

체크포인트마다 파일을 만들면 하루 6~10개가 쌓여 폴더가 터진다.

```markdown
# 2026-09-03  홍길동

## 15:10
로그인 3안 비교 끝. 소셜 단일 단계로 방향 정함.
→ LOG-0012 남김
다음: 기존 가입자 이전 방법 조사

## 11:45
경쟁 서비스 5개 가입 흐름 조사. 4개가 소셜 우선.
결정한 건 없음.

## 09:20
어제 이어서 로그인 플로우 검토 시작.
```

**최신이 맨 위에 온다.** 다음에 폴더를 열면 첫 항목만 읽어도 이어받을 수 있다.

한 항목에 들어갈 것은 세 가지다.

| | 내용 |
|---|---|
| 한 일 | 무엇을 했나 |
| 남긴 기록 | 의도 로그를 만들었으면 번호 |
| 다음 | 이어서 할 것 |

**"결정한 건 없음"도 그대로 쓴다.** 조사만 한 시간대는 그렇게 남는 게 정직하다. 억지로 결정을 만들면 로그가 오염된다.

30일이 지나면 월별로 압축한다 (`2026-08-요약.md`). 3주 전 근황은 아무도 안 읽는다.

> **결정은 영원히, 근황은 잠깐만.**

## 얼마나 자주 — 빈도 제어

| 상황 | 처리 | 기준 |
|---|---|---|
| 5턴 안에 두 번 발동 | 두 번째는 건너뜀 | `MIN_GAP=5` |
| 10턴 동안 무발동 | 안전망 발동 | `INTERVAL=10` |
| 30턴 넘게 무발동 | 경고 — 트리거 고장 | `STUCK=30` |
| 잡담만 10턴 | 찍되 "특별한 진전 없음" 한 줄 | |
| 체크포인트 중 오류 | 로컬에만 쓰고 다음에 재시도 | **작업은 안 끊는다** |

**사용자에게 묻지 않는다.** "지금 정리할까요?"를 10턴마다 물으면 그게 방해다. 조용히 처리하고 **"방금 정리했습니다"** 한 줄만 남긴다.

## 어떻게 도는가 — hook 과 Claude 의 역할 분담

**셸 스크립트는 요약을 쓸 수 없다.** 그래서 역할을 나눈다.

```
Stop hook (매 턴)
   └─ count_turns.sh  →  .local/turn_count 를 +1
                          판단은 하지 않는다. 세기만 한다

UserPromptSubmit hook (입력 직전)
   └─ checkpoint_gate.sh  →  .local/last_checkpoint_turn 과 비교
                             시점이면 "지금 정리하세요"를 Claude 에게 전달

PreCompact hook (압축 직전)
   └─ checkpoint_gate.sh --force  →  무조건 전달

Claude
   └─ 작업 노트·의도 로그 작성 → 공유
      끝나면 checkpoint_gate.sh --done 으로 카운터 리셋
```

**`--done` 을 빼먹으면 다음 턴에 또 발동한다.** 정리를 마쳤으면 반드시 호출한다.

상태 파일은 둘뿐이다.

| 파일 | 내용 |
|---|---|
| `.local/turn_count` | 누적 턴 수 |
| `.local/last_checkpoint_turn` | 마지막 정리 시점의 턴 번호 |

`.local/` 이라 공유되지 않는다. 사람마다 다른 값이고 팀이 알 필요가 없다.

`SessionEnd` 는 쓰지 않는다. 전체 1.5초 예산을 공유해서 무거운 작업이 잘린다.

## 자동 기록이 안 될 때

```bash
scripts/verify_hooks.sh
```

| 판정 | 뜻 | 대응 |
|---|---|---|
| `active` | 정상 | — |
| `untrusted` | 턴이 안 세어짐 | 폴더 신뢰 미수락. 재시작 후 "예" |
| `failed` | 세어지는데 기록이 안 됨 | 스크립트 경로 확인. 수동 정리로 버틴다 |

**세팅 직후에는 `untrusted` 가 정상이다.** 턴이 아직 안 쌓였을 뿐이다. 이걸 실패로 처리하지 않는다.

진짜 문제는 **작업을 시작하고 몇 턴 지난 뒤에도** 같은 판정이 나올 때다. 이 경우 기록이 하나도 안 남는데 **아무 오류도 안 난다.** 대시보드에 「자동 기록이 꺼져 있습니다」를 띄우고 켜는 법을 안내한다.

**조용히 실패하는 것이 가장 나쁘다.**

수동으로 찍을 수도 있다.

```bash
scripts/checkpoint_gate.sh --force
```

## 자주 막히는 곳

| 상황 | 대응 |
|---|---|
| 정리했는데 다음 턴에 또 발동 | `--done` 을 안 불렀다 |
| 너무 자주 발동 | 5턴 중복 방지가 도는지 확인. 안 되면 `--done` 누락 |
| 30턴 경고가 떴다 | hook 이 죽었거나 `--done` 만 계속 불린 것 |
| 오늘 작업 노트가 없다 | 새로 만든다. 첫 항목이 맨 위 |
| 하루가 넘어감 | 날짜가 바뀌면 새 파일 |
| 쓸 내용이 없다 | "특별한 진전 없음" 한 줄. 건너뛰지 않는다 |
| 결정이 없다 | 의도 로그를 만들지 않는다. 작업 노트만 |
| 공유가 실패 | 로컬에만 쓰고 다음에 재시도. **작업은 안 끊는다** |

더 많은 예외는 `troubleshooting.md` 에 있다.
