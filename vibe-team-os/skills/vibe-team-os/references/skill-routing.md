# 다른 스킬 부르기

## 목차

- 문제 — 깔아놓고 안 부른다
- 언제 무엇을 부르는가
- 부르기 전에 확인할 것
- 막힌 스킬 — 계열을 먼저 확인한다
- 한 번에 하나만
- 없을 때
- 자주 막히는 곳

---

## 문제 — 깔아놓고 안 부른다

세팅에서 스킬이 설치돼 있는지 확인한다. 그런데 **확인만 하고 실제로 부르지 않는 일이 생긴다.**

Claude 는 스킬을 **과소 호출하는 경향**이 있다. 쓰면 좋은 상황인데도 그냥 지나간다. 그리고 안 불러도 **아무 오류가 안 난다** — 결과가 조금 나빠질 뿐이라 눈치채기 어렵다.

그래서 "있으면 쓴다"가 아니라 **"이 상황이면 부른다"** 로 못 박는다.

---

## 언제 무엇을 부르는가

### `idea2planning` — 기획 문서를 만들 때

| 부른다 | 안 부른다 |
|---|---|
| 1-pager 를 만들 때 | 의도 로그를 쓸 때 (그건 이 스킬이 한다) |
| PRD 초안을 잡을 때 | 짧은 메모를 남길 때 |
| 목차를 합의할 때 | 이미 있는 문서를 고칠 때 |
| 화면 구조를 그릴 때 | |

**`phase: planning` 에서 "문서를 만들자"는 말이 나오면 부른다.**

이 스킬은 1-pager → PRD → 와이어프레임 순서를 갖고 있다. 그 순서를 따르면 기획이 빠진 데 없이 채워진다.

### `eli5` — 사용자가 이해를 못 할 때

| 부른다 | 안 부른다 |
|---|---|
| "이게 무슨 말이야?" | 사용자가 이미 아는 주제 |
| "쉽게 설명해줘" | 단순한 사실 확인 |
| 팀원에게 설명할 문구를 만들 때 | |
| 발표용으로 눈높이를 낮출 때 | |
| **비개발자에게 기술적인 걸 설명해야 할 때** | |

마지막 줄이 중요하다. **사용자가 요청하지 않아도** 상대가 비개발자인 게 분명하면 먼저 제안한다. 이 제품의 사용자 대부분이 Git 을 모르는 사람들이다.

### `humanize-korean` — 글에서 AI 티를 뺄 때

| 부른다 | 안 부른다 |
|---|---|
| PRD 최종본을 다듬을 때 | 의도 로그 (기록이라 다듬을 이유 없음) |
| 발표 자료 문장을 고칠 때 | 팀 내부 메모 |
| 팀원에게 보낼 안내문 | |

**`humanize-korean` 을 직접 부른다.** `/humanize` 는 사람이 치는 진입 명령이라 AI 가 못 부르는데, 그 안에서 도는 파이프라인이 `humanize-korean` 이고 이건 자동 호출된다. 한글 문서라면 이쪽을 쓰면 된다.

### Phase 2 — 개발 단계

| 스킬 | 언제 |
|---|---|
| `ponytail` | **코드를 쓰거나 고칠 때 상시.** 최소 구현을 강제해 diff 를 줄인다 |
| `karpathy-guidelines` | **코드를 고칠 때 상시.** 주변을 안 건드리게 해 diff 를 줄인다 |

앞의 둘은 겹침 예방책이다. diff 가 작으면 합치기가 그냥 성공한다.

### `supanova` 계열 — 이름만 보고 배제하지 않는다

네 개가 있고 **용도가 다르다.** "랜딩 페이지 엔진"이라는 이름 때문에 대시보드에 안 쓰려 했는데, 열어보니 **금지 폰트·한글 행간·카드 구조·간격 리듬**이 도구 화면에도 그대로 적용됐다.

| 스킬 | 언제 | 랜딩 전용? |
|---|---|---|
| `supanova-design-engine` | **새** 랜딩·발표 페이지를 처음부터 만들 때 | ✅ 그렇다 |
| **`supanova-premium-aesthetic`** | **아무 화면이든** 타이포·간격·카드·한글 리듬을 올릴 때 | ❌ 아니다 |
| **`supanova-redesign-engine`** | **이미 있는 화면**을 감사해서 개선할 때 | ❌ 아니다 |
| `supanova-full-output` | 잘림 없이 완전한 HTML 을 뽑아야 할 때 | ❌ 아니다 |

**와이어프레임 단계에는 넷 다 쓰지 않는다.** 구조를 잡는 단계이지 꾸미는 단계가 아니다.

**도구 화면(대시보드)에 쓸 때는 랜딩 전용 규칙을 걸러낸다.** 거대 히어로·CTA 강조·3단 카드·캐러셀·패럴랙스·마퀴는 빼고, 타이포·간격·카드·한글·상호작용만 가져온다. 매일 3초 훑는 화면은 **밀도와 예측 가능성**이 무기다.

---

## 부르기 전에 확인할 것

```
1. 지금 단계가 맞나         phase 를 본다
2. 설치돼 있나              .team/skills.yaml 과 실제 설치 경로
3. 자동 호출이 되나          막혀 있으면 같은 계열에 열린 게 있는지 본다
```

`skills.yaml` 에 있다고 설치된 것은 아니다. **명세와 실제는 다를 수 있다.** 세팅 이후 팀원이 환경을 바꿨을 수도 있다.

---

## 막힌 스킬 — 계열을 먼저 확인한다

일부 스킬은 프론트매터에 `disable-model-invocation: true` 가 있어 **AI 가 부를 수 없다.** 그런데 **막힌 것은 대개 사람이 치는 진입 명령이고, 실제 일을 하는 알맹이는 열려 있다.**

| 스킬 | 자동 호출 | 정체 |
|---|---|---|
| `humanize` | 🔒 불가 | 사람이 치는 진입 명령 (`/humanize`) |
| **`humanize-korean`** | ✅ **가능** | **실제 윤문 파이프라인 — 이걸 부른다** |
| `humanize-redo` | 🔒 불가 | 재실행 명령 |

**같은 계열인데 다르다.** 진입 명령만 막혀 있고 알맹이는 열려 있다. 한글 문서를 다듬을 때는 `humanize-korean` 을 직접 부르면 된다.

다른 스킬에서도 같은 구조가 나올 수 있다 — **막혀 있다고 포기하기 전에 같은 계열에 열린 게 있는지 본다.** `skills.yaml` 에 `manual_only: true` 로 표시된 것만 안내로 돌린다.

**정말 못 부르는 것은 대신 안내한다.**

```
이 기능은 제가 직접 부를 수 없습니다. `/명령어` 를 입력해 주세요.
```

조용히 건너뛰지 않는다. 안내를 안 하면 사용자는 그 기능이 있는 줄도 모른다.

---

## 한 번에 하나만

의존 스킬은 전부 **단일 파일**이다 (참조 파일 없음). 부르면 100~250줄이 통째로 대화에 들어온다.

```
5개를 동시에 부르면  →  1000줄이 들어와 정작 지금 지침이 묻힌다
```

**단계에 맞는 것 하나만 부른다.** 기획 중이면 `idea2planning` 하나, 설명이 필요하면 `eli5` 하나다.

이 스킬 자신도 같은 원칙으로 만들어졌다 — `SKILL.md` 는 라우터만 하고 참조 파일을 하나씩 읽는다.

---

## 없을 때

| 등급 | 없으면 |
|---|---|
| `required` (`idea2planning`) | 세팅 실패. 진행하지 않는다 |
| `optional` (`eli5` · `humanize-korean`) | **조용히 건너뛴다.** 대신 직접 처리한다 |
| `deferred` (Phase 2 것들) | 개발 단계 진입 시 설치 |

`optional` 이 없다고 작업을 멈추지 않는다. `eli5` 가 없으면 그냥 쉽게 설명하면 된다. 스킬은 품질을 높이는 것이지 없으면 못 하는 게 아니다.

**설치 직후에는 인식이 안 될 수 있다.** 파일은 있는데 목록에 안 뜨면 **Claude Code 재시작**을 안내한다. 실제로 관측된 현상이다.

---

## 자주 막히는 곳

| 상황 | 대응 |
|---|---|
| 부를 상황인지 애매함 | 위 표의 「부른다」에 해당하면 부른다. 애매하면 안 부른다 |
| 스킬이 목록에 없음 | 파일이 있는지 먼저 확인. 있으면 재시작 안내 |
| 문서를 다듬어야 함 | `humanize-korean` 을 부른다. `/humanize` 안내는 불필요 |
| 화면 디자인을 올려야 함 | 새로 만들면 `design-engine`, 이미 있으면 **`redesign-engine`** |
| 스킬 이름이 용도와 안 맞아 보임 | **열어서 내용을 본다.** 이름만 보고 배제하지 않는다 |
| 두 개가 동시에 필요 | 하나씩 순서대로. 동시에 부르지 않는다 |
| `optional` 이 없음 | 조용히 건너뛰고 직접 처리 |
| 스킬 결과가 지침과 충돌 | **이 스킬의 「항상 지키는 것」이 우선한다** |
| 사용자가 특정 스킬을 지목 | 단계와 안 맞아도 부른다. 사용자 요청이 우선 |

마지막 두 줄이 중요하다. 다른 스킬이 "이렇게 써라"고 해도 **Git 용어 미노출·근거 없으면 빈칸** 같은 원칙은 그대로 지킨다.
