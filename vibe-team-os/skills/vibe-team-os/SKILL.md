# 바이브 팀 OS

Git을 몰라도 여러 명이 AI로 함께 만들 수 있게 하고, 그 과정에서 **왜 그렇게 결정했는지가 자동으로 남게** 한다.

## 먼저 할 일: 지금 어느 단계인가

`.team/config.json`의 `phase`를 읽는다. 파일이 없으면 세팅이 안 된 프로젝트다.

| phase | 읽을 파일 |
|---|---|
| 파일 없음 · `setup` | `references/setup.md` |
| `planning` | `references/intent-log.md` |
| `merging` | `references/merge.md` · **미작성 — 열면 설계 문서로 안내** |
| `presenting` | `references/report.md` · **미작성** |
| 오류가 났을 때 | `references/troubleshooting.md` · **미작성** |

**한 번에 하나만 읽는다.** 단계가 바뀌면 그때 다음 것을 읽는다. 전부 미리 읽으면 정작 지금 필요한 지침이 대화에 묻힌다.

## 항상 지키는 것

단계와 무관하게 지킨다. 이 여섯 개만 본문에 둔다.

**1. Git 어휘를 사용자에게 노출하지 않는다**
팀원 대부분은 Git을 모른다. "커밋" 같은 말이 나오는 순간 "내가 모르는 영역"이 되어 손을 뗀다. 아래 「사용자에게 쓰는 말」을 따른다.

**2. 근거가 없으면 의도를 빈칸으로 둔다**
사용자가 말하지 않은 이유를 추측해서 적으면, 그 추측이 영구 기록이 되고 PRD 근거가 되고 발표 자료까지 간다. **본인이 하지도 않은 생각이 발표에 실린다.** 인용할 발언이 없으면 `confidence: unconfirmed`로 두고 빈칸으로 남긴다. 모르는 건 모른다고 쓰는 게 이 제품의 신뢰를 지킨다.

**3. 사람이 아니라 안(案)을 평가한다**
"김철수 것은 품질이 미달" 대신 "A안이 요구사항 3.2를 충족하지 못함"으로 쓴다. 그 기록을 당사자가 읽는다. 그리고 공개 저장소면 인터넷 전체가 읽는다.

**4. 상반된 의견을 임의로 절충하지 않는다**
AI가 반반 섞으면 양쪽 다 자기 의견이 왜곡됐다고 느낀다. 두 안을 그대로 보여주고 사람이 고르게 한다. 그 선택도 다시 기록으로 남긴다.

**5. 공유 전에 검사 스크립트를 실행한다**
`scripts/scan_secrets.sh`와 `scripts/check_sensitive.sh`를 돌린다. 종료 코드 2면 중단한다. 저장소가 공개일 수 있고, 한 번 새어나간 것은 되돌릴 수 없다.

**6. 기록을 물리적으로 지우지 않는다**
철회된 결정은 `status: 폐기`로만 바꾼다. "이건 안 하기로 했다"도 정보이고, 같은 아이디어가 다시 나올 때 근거가 된다.

## 사용자에게 쓰는 말

| 내부 개념 | 사용자에게 |
|---|---|
| commit | 저장 |
| push | 공유 |
| pull / fetch | 받아오기 |
| branch | 작업 중인 코드 |
| merge | 합치기 |
| conflict | 겹침 |
| revert | 되돌리기 |
| RLS / 권한 정책 | 팀원만 볼 수 있게 하는 설정 |
| workspace trust | 폴더 신뢰 |

"충돌"이 아니라 **"겹침"**이다. 충돌은 싸움을 연상시키고 겹침은 상태를 서술한다. 겁먹으면 공유를 미루고, 공유를 미루면 문제가 커진다.

## 기록은 네 층으로 나뉜다

| 층 | 무엇 | 어디 | 수명 |
|---|---|---|---|
| 원본 대화 | 전문 | `.local/sessions/` | 로컬만, 공유 안 함 |
| 작업 노트 | "어제 어디까지 했지" | `members/<이름>/notes/` | 30일 후 월별 압축 |
| 의도 로그 | "왜 그렇게 정했지" | `members/<이름>/logs/` | 영구 |
| 팀 결정 | "우리 약속이 뭐였지" | `decisions/` | 영구 |

**결정은 영원히, 근황은 잠깐만.** 대화를 통째로 남기면 양이 많아 아무도 안 읽는다.

## 언제 기록하나 — 체크포인트

세션이 끝나기를 기다리지 않는다. GUI로 하루 종일 한 세션을 열어두면 끝이 오지 않는다.

| 우선 | 시점 |
|---|---|
| 0 | 대화가 압축되기 직전 (`PreCompact`) — 여기서 놓치면 맥락이 사라진다 |
| 1 | 작업 한 덩어리가 끝났을 때 (주제 전환·결정 도출·산출물 완성) |
| 2 | 10턴 동안 한 번도 안 찍혔을 때 (안전망) |

체크포인트에서 세 가지를 한꺼번에 한다 — **작업 노트 갱신 · 의도 로그 생성 · 상태 공유**.

사용자에게 "지금 정리할까요?"라고 묻지 않는다. 10턴마다 물으면 그게 방해다. 조용히 하고 "방금 정리했습니다" 한 줄만 남긴다.

## 참조 파일

필요할 때만 읽는다. 읽지 않으면 대화 공간을 전혀 쓰지 않는다.

| 파일 | 언제 읽나 |
|---|---|
| `references/setup.md` | 새 프로젝트를 시작할 때 |
| `references/intent-log.md` | 기획 중 — 로그 형식과 되묻기 규칙 |
| `references/checkpoint.md` | 체크포인트 동작을 정확히 알아야 할 때 |
| `references/merge.md` | 기획을 PRD로 합칠 때 · **미작성 — 설계 문서로 안내** |
| `references/report.md` | 발표물을 만들 때 · **미작성** |
| `references/skill-routing.md` | 다른 스킬을 불러야 할 때 |
| `references/policies.md` | 상태값·정책 정의 · **미작성** |
| `references/troubleshooting.md` | 오류가 났을 때 · **미작성** |

**미작성 표시가 붙은 것은 아직 내용이 없다.** 열면 대신 읽을 설계 문서를 알려준다. 없는 걸 있는 것처럼 적어두면 읽으러 갔다가 빈손으로 돌아온다.

## 다른 스킬 부르기

깔려 있어도 안 부르면 소용없다. **Claude 는 스킬을 과소 호출하는 경향이 있고, 안 불러도 오류가 나지 않는다.** 결과가 조금 나빠질 뿐이라 눈치채기 어렵다. 그래서 "있으면 쓴다"가 아니라 아래 상황이면 **부른다**.

| 이런 상황이면 | 부른다 | 없으면 |
|---|---|---|
| 기획 문서(1-pager·PRD·와이어프레임)를 만든다 | `idea2planning` | **세팅 실패** |
| 사용자가 "무슨 말이야" 하거나, **비개발자에게 기술적인 걸 설명해야 한다** | `eli5` | 조용히 건너뜀 |
| 문서 문장의 AI 티를 빼야 한다 | `humanize-korean` | 조용히 건너뜀 |
| 코드를 쓰거나 고친다 | `ponytail` + `karpathy-guidelines` | 그때 설치 |
| **새** 랜딩·발표 페이지를 만든다 | `supanova-design-engine` | 그때 설치 |
| **이미 있는 화면**의 디자인을 올린다 | `supanova-redesign-engine` | 그때 설치 |

**"없으면" 열이 중요하다.** `idea2planning` 만 필수고 나머지는 없어도 작업이 멈추지 않는다. `eli5` 가 없으면 그냥 쉽게 설명하면 된다 — **스킬은 품질을 높이는 것이지 없으면 못 하는 게 아니다.**

마지막 둘은 미리 깔지 않는다. **필요한 단계에 가서 설치한다** — `supanova` 는 개발 단계뿐 아니라 발표 페이지를 만들 때도 쓰인다.

**한 번에 하나만 부른다.** 의존 스킬은 전부 단일 파일이라 하나가 100~250줄이다. 여러 개를 부르면 정작 지금 필요한 지침이 대화에 묻힌다.

**다른 스킬이 뭐라고 하든 위 「항상 지키는 것」이 우선한다.**

판단이 애매하면 `references/skill-routing.md` 를 읽는다.

## 무겁게 읽는 일은 위임한다

로그 60건을 통째로 읽으면 ≈24k 토큰이다. 메인 대화가 그걸로 들어차면 **정작 판단에 쓸 여유가 없어진다.**

| 서브에이전트에 위임 | 메인에서 |
|---|---|
| 로그 수집·분류, 전수 조사 | **결정** |
| 발표물 초안 생성 | **충돌 양자 제시** |
| 무거운 스킬 실행 (`humanize-korean` · `supanova`) | 사용자와의 대화 |

**결정은 절대 위임하지 않는다.** 서브에이전트가 "이건 충돌"이라 판정하고 사람이 못 보면, AI 가 절충한 것과 같아진다.

**찾을 때는 통째로 읽지 말고 `grep` 으로 추린다.**

```bash
grep -l "topic: 로그인" members/*/logs/*.md
grep -l "links:.*PRD-3.2" members/*/logs/*.md
```

자세한 기준은 `docs/11-설계-토큰절약.md`.

## 스크립트

읽지 말고 **실행한다**. 판단이 필요 없는 일은 코드가 하는 게 정확하다.

| 스크립트 | 하는 일 |
|---|---|
| `scripts/scan_secrets.sh` | 키·토큰 검사. 발견 시 종료 코드 2 |
| `scripts/check_sensitive.sh` | 인물 평가·대외비 표현 검사. 발견 시 종료 코드 2 |
| `scripts/verify_setup.py` | 세팅 완료 판정. 통과 못 하면 완료 처리하지 않음 |
| `scripts/verify_rls.sh` | DB 권한 침투 검사. 하나라도 뚫리면 세팅 실패 |
| `scripts/verify_hooks.sh` | 자동 기록이 실제로 도는지 확인. `--record` 로 판정을 status 파일에 적는다 |
| `scripts/restore_context.sh` | 세션 시작 시 맥락 복원 |
| `scripts/count_turns.sh` | 턴 카운터 증가 |
| `scripts/checkpoint_gate.sh` | 체크포인트 시점 판정 |
| `scripts/validate_log.py` | 로그 형식 검증 |
| `scripts/build_dashboard.py` | 대시보드 데이터 빌드 (`.team/*` → `docs/data/`) |

차단이 필요한 스크립트는 **종료 코드 2**를 쓴다. 1은 차단되지 않고 그냥 진행된다.

## 자동 실행

`hooks/hooks.json` 이 아래를 자동으로 처리한다. 사용자가 아무것도 하지 않아도 된다.

**hook 을 SKILL.md 프론트매터에 두지 않는 이유** — 프론트매터의 hook 은 **스킬을 부른 뒤에야**
등록된다. 깔아만 두면 안 돈다. 특히 `SessionStart` 는 구조상 영원히 못 뜬다 —
세션이 시작된 다음에야 스킬을 부를 수 있기 때문이다.
그래서 이 스킬은 `.claude-plugin/plugin.json` 을 두어 **플러그인으로 로드**한다.
플러그인 hook 은 호출과 무관하게 세션 시작 때 등록된다.

| 시점 | 하는 일 |
|---|---|
| 세션 시작 | 어제 어디까지 했는지 브리핑 — **기록의 즉시 보상** |
| 매 턴 | 턴 세기 (판단 없음, 세기만) |
| 입력 직전 | 체크포인트 시점인지 판정 |
| 대화 압축 직전 | 무조건 체크포인트 — 여기서 놓치면 맥락이 사라진다 |
| 공유 직전 | 비밀정보·민감표현 검사 |

`SessionEnd` 는 쓰지 않는다. 전체 1.5초 예산을 공유해서 무거운 작업이 잘린다.

**셸은 요약을 쓸 수 없다.** 그래서 hook 은 "지금이 그 시점"이라고 알려주기만 하고, 실제 기록은 Claude 가 한다. 마치면 `scripts/checkpoint_gate.sh --done` 을 실행해 카운터를 리셋한다.

hook 은 등록만 되고 안 돌 수 있다 — 폴더 신뢰를 수락하지 않으면 실행되지 않는데, 이때 **아무 오류도 없이 기록만 안 남는다.** `verify_hooks.sh` 로 확인하고, 안 돌면 대시보드에 **"자동 기록이 꺼져 있습니다"** 를 띄운다. 조용히 실패하는 것이 가장 나쁘다.
